# Media Insight · 境外媒体舆情检索与总结提炼

一个纯静态的舆情跟踪工具，托管于 GitHub Pages，无需服务器、无需安装。

**固定网址**：https://patfang0105.github.io/media-insight/

## 能做什么

- 输入中文或英文话题，自动译为英文关键词后检索境外媒体报道
- **默认只勾选「全球新闻池」**：抓取发生在 GitHub 的境外服务器，结果写入本仓库的 `news-data.json`，页面读取的是自己网站里的文件——不跨境、不受 CORS 限制、不受 GDELT 5 秒限流影响，也**完全不依赖、不触碰 `my-rss-blog`**
- 三类检索源可任意组合：全球新闻池（主源）／RSS 精选源（可选，你的订阅快照）／实时检索 GDELT（可选，浏览器直连，国内网络下常被限流）
- 概览显示「全球新闻池 N 篇 / 实时检索 M 篇 / RSS 精选源 K 篇」来源构成，并标注新闻池的生成时间；只勾 GDELT 且失败时会明确报错，不再悄悄回退 RSS
- **检索完成后自动提炼全部命中报道，无需勾选、无需点任何提炼按钮**：逐篇生成中文标题、中文要点、中文摘译，并保留英文原文关键句以便核对
- 同时输出共识线索、立场差异、数字信号与信息局限；报告覆盖本次检索命中的每一篇
- 翻译走 Google gtx（支持长文本、并发），失败自动重试并降级 MyMemory，译文在本机缓存复用；仍失败则保留英文原文并如实标注
- 无公开摘要的条目（GDELT artlist 只提供标题与链接）只给出中文标题译名并明确标注，不据此推断正文
- 内置免配置提炼；也可在设置里填 OpenAI 兼容 LLM API 获得更高质量结果，调用失败自动降级
- 付费墙媒体逐条标注访问级别，仅使用其公开摘要，不绕过付费验证
- 报告直接在页面「4 · 总结提炼结果」区完整呈现，**不提供下载功能**

## 新闻池是怎么更新的

`.github/workflows/update-news.yml` 每 3 小时（UTC 第 17 分钟）自动运行一次，也可在仓库 **Actions → 更新全球新闻池 → Run workflow** 手动触发：

1. 在 GitHub 的境外 runner 上按 **21 类长期话题**（APEC／中美贸易／关税／AI 监管／半导体／利率／俄乌／中东／油价／气候／欧洲政治／金融市场／平台反垄断／供应链稀土／公共卫生／移民／国防／外交／新兴市场／金融科技／全球综合要闻）抓取 GDELT DOC API
2. GDELT 被限流时自动用 **Google News RSS** 作为独立备用源补位
3. 与仓库里已有的 `news-data.json` 合并去重，按时间倒序保留最多 1600 篇 / 45 天
4. 把新数据提交回本仓库，GitHub Pages 自动发布，页面下次检索即读到新内容

脚本 `scripts/fetch_news.py` 只用 Python 标准库，遵守 GDELT 5 秒限速、429 退避重试，并设有 12 分钟总时间预算；若本次全部抓取失败，**保留上一次成功的数据并标记 `stale`**，绝不写空文件。

首版 `news-data.json` 由真实 GDELT 抓取结果与公开网页检索结果（含英文导语/摘要）构成，共 279 篇 / 212 家来源；上线后由 Actions 自动扩充，无需人工维护。

> 仓库设置要求：Settings → Actions → General → Workflow permissions 选 **Read and write permissions**，否则定时任务无法把 `news-data.json` 提交回仓库。

## 使用与隐私说明

- 页面无服务端、无账号体系；检索、筛选与提炼全部在访问者浏览器内完成。抓取与写库由 GitHub Actions 在本仓库内完成，与访问者无关。
- 翻译时仅向公开翻译接口发送报道的公开标题与摘要文本，不含任何个人信息。
- 检索历史、自动提炼开关、译文缓存与新闻池快照保存在各自浏览器的 localStorage，不跨设备共享。
- 免费翻译接口有配额，短时间高强度连续检索可能触发限流；此时自动重试与补译，仍失败会保留英文原文并如实标注，不会让页面卡住。命中数超过 300 篇时按相关度取前 300 篇进入清单与提炼，并在概览提示。
- 新闻池按预设长期话题定期抓取，**冷门或突发话题可能尚未入池**；此时会放宽为按时间列出近期报道并提示，可加勾「实时检索 GDELT」或稍后再试。
- 对 `my-rss-blog` 仅在你主动勾选「RSS 精选源」时发起只读 GET：尊重 ETag 缓存、本机留存快照、故障时降级不重试，不影响源站运行。
- 仓库内无任何密钥或凭据；GitHub Actions 使用平台自动提供的 `GITHUB_TOKEN`。
